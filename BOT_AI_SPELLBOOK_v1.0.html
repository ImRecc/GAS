零、彻底看懂那些英文缩写：用“特种小队”比喻秒懂全套名词

把每一只 Bot 想象成一个拿着步枪的战术士兵，下面这 8 个专业缩写其实就对应士兵身上的 8 个器官或角色：

① ST = StateTree（状态树大脑，资产：ST_Enemy_Arena）

人话比喻：士兵脑子里的“3 间工作房流程图”。房间 A 叫“挨打硬直室”，房间 B 叫“开火进攻室”，房间 C 叫“跑位机动室”。

核心价值：它只管“什么时候进哪间房、什么时候换房”，不管具体怎么开枪。所以全场近战怪、远程怪、炮塔怪、精英怪，甚至以后做的 Boss，100% 共用这同一张大脑图！

② STE = StateTree Evaluator（态势评估器，蓝图：STE_EnemyCombatContext）

人话比喻：士兵头盔上的“战术雷达 / 仪表盘”。只要大脑开着，它就在后台持续运转（每 0.1 秒扫描一次），把“敌人在哪（TargetActor）、离我多远/夹角多少/有没有墙（CombatInfo）、我有没有被打懵（bIsStaggered）”实时贴到公共白板上，让 3 个房间直接看。

③ STT = StateTree Task（状态树任务，蓝图：STT_Enemy*）

人话比喻：每个房间里“真正动手干活的工人”。每个 STT 只有 3 个生命周期钩子：

• EventEnterState（刚推门进屋）：干一次性动作（如选招、抢令牌、下达移动）；
• EventTick（待在屋里每帧）：盯状态（如看招放完没、看 1.2s EQS 冷却到没）；
• EventExitState（离开房间收尾）：擦屁股（如交还令牌、取消注视）。

④ EQS = Environment Query System（环境查询系统，资产：EQS_Bot_*）

人话比喻：士兵眼里的“战术沙盘推演”。普通 MoveToActor 只会傻乎乎直线朝玩家冲；而 EQS 会在地面撒一圈候选点（Generator 生成器），再用尺子和射线逐个淘汰和打分（Tests 测试项：“这里能看到敌人吗？有没有墙挡着？离队友远不远？”），最后挑出最高分的点走过去！

⑤ Director = UEnemyCombatDirector（全场进攻令牌裁判，C++ WorldSubsystem）

人话比喻：拳击台边的“发牌裁判”（关卡一开自动存在，不用往地图里拖）。手里默认只有 2 张近战牌、2 张远程牌。防止 8 只怪同时齐射把玩家瞬间融化！并且它懂“视野优先抢占”：你屏幕正前方看到的怪，可以直接抢走你背后看不见的怪手里的进攻牌！

⑥ BPI = Blueprint Interface（蓝图接口，资产：BPI_BotConfig）

人话比喻：大脑和身体之间的“USB 标准化接口”。大脑不关心下面接的是咕噜怪还是精英先锋，只需往接口问：“你的菜单是什么？你的走位风格是什么？”——彻底消灭蓝图之间的硬引用耦合（Hard Cast）。

⑦ DA = DataAsset（招式配置表，资产：DA_Moveset_*）

人话比喻：插进怪物身上的“红白机游戏卡带 / 招式菜单”。换一张卡带，怪物就会换一套完全不同的招式距离、夹角、冷却、权重和半血二阶段规则，完全不需要改大脑或写代码。

⑧ GAS = Gameplay Ability System（招式动作包与标签，资产：GA_bot_* / GA_Bot_Elite*）

人话比喻：每一招具体的“肌肉动作剧本”（画预警球 → 蓄力 → 扑击/发子弹/射激光 → 算伤害 → 后摇）。靠 GameplayTag 和大脑通信：一开招就贴上 State.Enemy.Attacking（告诉大脑“我正忙着呢别打扰”），一结束就撕掉标签（告诉大脑“打完了，交牌！”）。

一、一只 Bot 从出生到开火的完整生命链（全局数据流）

把上面 8 个零件串起来，每只 Bot 在游戏里的一生就是下面这张清晰流水线：

【1. 出生装填】(BP_enemyBase: EventBeginPlay)
  ├─ 给自己贴阵营标签 Team.Enemy（彻底支持 Bot vs Bot 混战）
  ├─ 遍历自己的招式表 DA_Moveset_xxx，自动把表里所有招式 GA 装进 ASC
  └─ 自动装入受击硬直技能 GA_Enemy_HitReact

【2. 大脑点火】(AIC_EnemyBase: EventOnPossess)
  ├─ Delay(0.0) 等一帧确保出生与阵营标签全部就绪
  └─ 检查双脑开关 bUseStateTreeBrain：
       ├─ True  → 启动 StateTreeAI (ST_Enemy_Arena) 【现役现代大脑】
       └─ False → 走旧版 F_EvaluateAI 定时器 【随时可勾选回滚对比】

【3. 侦察兵后台循环】(STE_EnemyCombatContext)
  ├─ TreeStart：用 CFLF_FindNearestHostileTarget 找到最近活体敌人 → 立刻算首帧 CombatInfo
  └─ 每 0.1s (10Hz)：更新 Distance2D / AngleToTarget / bHasLineOfSight / SelfHealthPercent
     每帧实时检查：ASC 有无 State.Enemy.Staggered？有无 State.Enemy.Attacking？

【4. 状态树三房流转】(ST_Enemy_Arena)
  ├─ ① 最高优先级：State: Staggered (bIsStaggered == true)
  │    └─ STT_EnemyStagger：立刻刹车 + 归还令牌，等硬直标签消失回 Root
  ├─ ② 次优先级：state:Attack (bIsStaggered == false)
  │    └─ STT_EnemyAttack：有视线? → PickBestEnemyMove 选招 → Director 抢牌 → 停脚 → 激活 GA → 记冷却
  │         ├─ 成功：等 0.05s 后盯住 !State.Enemy.Attacking → 打完交牌回 Root
  │         └─ 失败（没牌/太远/冷却中/无视线）：立刻跳转去 state:Positioning
  └─ ③ 兜底机动：state:Positioning (每 0.25s 尝试跳回 state:Attack 抽签)
       └─ STT_EnemyPositioning：盯住目标 SetFocus + 按 MoveStyle 走位：
            ├─ Stationary    → 原地停脚（炮塔）
            ├─ Chase         → MoveToActor 直线追击（近战）
            ├─ Skirmish      → 1.2s 硬锁跑 EQS_Bot_Flank 扇形包抄（远程/精英）
            └─ CoverSkirmish → 1.2s 硬锁：冷却好且有牌机会跑 Flank 探头，否则跑 Cover 缩墙（豺狼人）

【5. 死亡收尾】(BP_enemyBase: EventOnCharacterDeath)
  └─ 第一时间调用 ReleaseAttackToken(self) 把牌还给全场 → 物理布娃娃炸飞 → 花瓣掉落 → 3s 销毁
为什么这套架构能做到“改招式不改大脑、100% 兼容 BvB”？

铁律 1（零硬编码玩家）：全套系统里绝不出现 GetPlayerPawn(0)，所有索敌与 EQS 上下文均靠 Team.Player vs Team.Enemy 阵营标签互斥判定。
铁律 2（数据驱动）：状态树只认 BPI_BotConfig 与 UEnemyMovesetData，所以从普通杂兵升级到 4 招变招精英怪，C++ 和 StateTree 真的 1 行都没动！

二、StateTree 大脑核心件详解（ST / STE / STT）

#01
ST_Enemy_ArenaST 大脑/Game/bps/botAI/
通用竞技场状态树总控台

核心机制：Schema 为 StateTreeAIComponentSchema（自动把 Context.Actor 和 Context.AIController 注入所有评估器和任务）。Root 下按从上到下顺序评估 3 个子状态，谁满足进入条件就进谁。

3 大状态优先级与 3 处关键属性绑定 (Property Binding)
状态流转规则1. State: Staggered（进门条件：bIsStaggered == true，完成回 Root）
2. state:Attack（进门条件：bIsStaggered == false，成功回 Root，失败转 state:Positioning）
3. state:Positioning（无条件兜底；OnTick 硬直抢占去 Staggered；延时 0.25s 跳回 Attack 重试抽签）
3 处核心数据绑定• STT_EnemyStagger.bIsStaggered ← Evaluator.bIsStaggered
• STT_EnemyAttack.CombatInfo ← Evaluator.CombatInfo
• STT_EnemyPositioning.targetActor ← Evaluator.TargetActor
血泪防坑铁律（实机踩过的 2 个大坑）
  • 修改 Evaluator/Task 变量后必须手动点 ST 的 Compile：否则旧绑定可能把 TargetActor 覆写成 Self（我们已在 STE/STT 中加了 Target == Actor 自愈兜底）。
  • 不要在 Context 分类乱放自定义变量：Context 分类专供引擎自动注入自身 Actor / AIController，放别的东西会被强行塞进自身指针！
需求生成咒语（扩展状态树时怎么跟 AI 说）

我想给现有通用状态树 ST_Enemy_Arena 新增一个状态【例如：残血狂暴逃跑 / 巡逻待机】，请保持现有 Staggered > Attack > Positioning 优先级不变，告诉我应该在 STE_EnemyCombatContext 增加什么输出变量、新建什么 STT_ 任务蓝图，以及在 ST_Enemy_Arena 里怎么配置进入条件、绑定和过渡转移。

#02
STE_EnemyCombatContextSTE 侦察/Game/bps/botAI/
战斗态势评估器（10Hz 节流雷达）

它在干嘛：每帧轻量化检测 2 个 GAS 标签（State.Enemy.Staggered、State.Enemy.Attacking），每 0.1s 节流算一次几何态势 CFLF_GetEnemyCombatInfo；一旦目标死亡或失效，下个 0.1s 周期自动调 CFLF_FindNearestHostileTarget 动态转火。

  • 调参位置：节流间隔目前是 0.1s（10Hz），同屏超过 30 只怪时可放宽到 0.15~0.2s 进一步省 CPU。

三、EQS 战术走位沙盘专题（扇形包抄 & 豺狼人找掩体）

全 UE5 最容易踩反的 EQS 铁律（已在 UE5.8 引擎源码实锤！）

UE5 的 EnvQueryTest_Trace 会自动把目标 Actor（Context）加入忽略列表！因此射线撞到墙/柱子才返回 True，畅通无阻看到目标返回 False：
• 想找有清晰视线的开火点（EQS_Bot_Flank） → Bool Match 必须取消勾选（False）！
• 想找被墙挡住视线的掩体点（EQS_Bot_Cover） → Bool Match 必须勾选（True）！

#06
EQS_Bot_FlankEQS 沙盘/Game/bps/botAI/EQS/
远程扇形包抄查询（16 点极轻量 Donut）
生成器 + 3 条打分规则（单次耗时实测仅 ~1ms）
Generator：Points: Donut（围绕 Target 撒点）InnerRadius = 550，OuterRadius = 950，2 环 × 8 点 = 16 个点，投影到 NavMesh。
Test 1：Trace（Filter Only，筛掉被墙挡住的点）向 Bot EQS Context - Target 发 Visibility 射线（高度偏移 +60），Bool Match = False。
Test 2 & 3：Distance（Score Only，既散开又省路）离 Bot EQS Context - Allies 越远分越高（+1.0，防队友扎堆）；离自己 Querier 越近分略高（-0.4，优先顺手侧翼点）。
  • 想调宽/调近交战距离？直接双击打开 EQS_Bot_Flank，改 InnerRadius / OuterRadius 即可，零代码改动！
#07
EQS_Bot_CoverEQS 沙盘/Game/bps/botAI/EQS/
《光环》豺狼人找掩体查询（Grid 网格）
生成器 + 4 条筛选与打分规则
Generator：Points: Grid（围绕自己 Querier 撒点）Grid Half Size = 700，Space Between = 175，投影到 NavMesh。
Test 1 & 2：Trace + Distance（Filter Only）向 Target 发射线（+60），Bool Match = True（必须有墙遮挡！）；且到 Target 距离限定在 350 ~ 1400 cm（不贴脸也不逃跑）。
Test 3 & 4：Distance（Score Only）离自己越近分越高（-1.0，就近秒缩掩体）；离队友越远分越高（+0.5，分头躲不同柱子）。
#08
UBotEQSContext_Target / AlliesEQS 语境BotEQSContexts.h/.cpp
全阵营兼容的自定义 EQS 上下文

为什么必须写这两个 C++ 类？UE 自带的 EQS 上下文只有 Querier（自己），不知道“敌人是谁”和“队友是谁”。这两个类通过 AIController::GetFocusActor() + CFLF_FindNearestHostileTarget 和阵营标签扫描，让 EQS 在 玩家 vs Bot 和 Bot vs Bot 混战里都完全通用。

四、Bot 专属 C++ 算法与裁判底座速查

#09
UEnemyCombatDirectorDirectorEnemyCombatDirector.h/.cpp
全场进攻令牌裁判 + 低频 EQS 冷却锁

怎么调参（无需改代码！）：打开虚幻编辑器菜单 Edit → Project Settings → Game → Enemy Combat Director，直接滑动调整：

  • MaxMeleeTokens（默认 2）/ MaxRangedTokens（默认 2）：同时允许几只近战/远程怪出手；
  • TokenTimeoutDuration（默认 6.0s）：防死锁强制回收超时；
  • PlayerViewHalfAngleDeg（默认 45°，即 90° 前向视锥）与 PreemptionStrategy：视野优先抢占策略。

核心接口：TryRequestAttackToken（抢牌）、ReleaseAttackToken（还牌）、CanRequestAttackToken（只读探测池有无空位，解开豺狼人躲墙死锁）、TryConsumeEQSCooldown（跨状态 1.2s 硬冷却锁）。

需求生成咒语

我想调整全场敌人并发进攻节奏，通过 UEnemyCombatDirector 将【近战/远程】令牌上限改为【X】，或者新增一种令牌类型【如 Heavy / Boss】并在 UEnemyCombatSettings 暴露配置项，请保持视野优先抢占与 6 秒防死锁机制不变。

#10
UEnemyMovesetData (DA_Moveset_*)DA 菜单EnemyMovesetData.h
数据驱动招式配置表

每行 FEnemyMoveRule 就是一招的“入场券门槛”，全部满足才会进入加权抽签池：

字段名策划调参人话说明
MoveTag / MoveAbilityClass招式的 GAS 激活标签（建议挂 Ability.Enemy.Attack.*）与对应技能蓝图类（出生自动装填）。
TokenTypeMelee / Ranged / None（绕背反制技设为 None 可无视令牌池立刻反击！）。
Min/MaxDistance纯 2D 水平射程（cm）。填 99999 ~ 99999 可实现“仅借 BeginPlay 装填，永不被大脑主动抽中”的纯连招派生技！
Min/MaxFrontAngle相对怪物正前方的水平夹角（0°正前 ~ 180°正后）。填 110° ~ 180° 就是专治绕背的反制扫击！
Min/MaxHealthPercent自身血量阶段门禁（如填 0.0 ~ 0.5 就是半血二阶段专属狂暴技）。
CooldownSeconds / Weight单招独立冷却秒数；加权随机权重（最小 0.001，越大越爱出这招）。

五、Bot 攻击技能 (GA) 4 条铁律与现役怪物图鉴

写任何 Bot 攻击 GA 必须严格遵守的 4 条铁律
1. Instancing Policy = Instanced Per Actor：技能实例挂在怪身上复用。
2. 标签树形挂载：AbilityTags 必须是 Ability.Enemy.Attack 或其子标签（如 Ability.Enemy.Attack.EliteDashSlam），保证 GA_Enemy_HitReact 能一刀全打断；ActivationOwnedTags 必须带 State.Enemy.Attacking（大脑靠它判断招放完没）。
3. 绝不用普通 Delay，必须用 GAS 原生 WaitDelay / RepeatAction：普通 Delay 在 InstancedPerActor 被取消打断时不会自动停止，会产生“怪都硬直了还飞出子弹/激光”的幽灵伤害！
4. 窗口期变招秘诀：派生招式（如 GA_Bot_EliteFollowupUppercut）把 ActivationBlockedTags 留空，前招在 EndAbility 之前先 TryActivateAbilitiesByTag 激活派生招，即可让 State.Enemy.Attacking 一帧不断裂，实现无缝连招！
